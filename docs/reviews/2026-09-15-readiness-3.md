## The finding that outranks everything else in this review series

### A confirmed defect, reproduced by execution — not a gap

`agent/aiscelapeus/triage.py:99-131`. Test-Behavior executed it; I reproduced it
independently:

```
set_level(4, "first")            -> True
set_level(4, "second rationale") -> False      # signals "nothing changed"
rationale now: 'second rationale'              # ...but it did change
history len: 2
   4 'first'
   4 'second rationale'
```

`set_level` returns `False` — the caller's signal that nothing changed — while mutating
`rationale` and appending a **second history entry for the same level**.

The consequence is a real divergence, not a cosmetic one. `agent.py:209-214` branches on
that `False` and **skips `record_fact`**, so the UI holds one rationale and the Moss
timeline holds another. `soap.py:37-40` renders `state.history` verbatim, so the clinical
record prints Level 4 twice with two different justifications.

Every prior finding in three reviews has been a *gap* — something absent. This is the first
confirmed *bug* in code that exists and runs.

> Test-Behavior's point about the test that would miss it is the sharper half: the obvious
> first assertion, `assert state.set_level(2, "r") is False`, **passes against this bug**,
> because it observes the return flag and never reads `history` or `rationale`.

## Convergence within this round

### P1. The latency claim is unproven *and* structurally misattributable — Prove-It-Works + Shared State

Two personas, opposite directions, same target — the one claim the Moss sprint is judged on.

**It has never been measured.** `agent/scripts/seed_moss.py:38-63` is the only artifact in
the repo that measures Moss retrieval. Verified: `agent/scripts/` has **no `__pycache__`**
while `agent/aiscelapeus/__pycache__/` holds ten `.pyc` files from 07:38 today, and **no
`.env.local` exists anywhere** in the tree — `config.py:57` raises on a missing
`MOSS_PROJECT_ID`, so the script cannot have completed. Every latency number in the README,
in NFR-001 (marked **BUILT**), and in the demo plan traces to an execution that left no log,
no output, no artifact.

**And the number can be attached to the wrong query.** `moss_context.py:107` declares
`last_trace` as a single shared slot; `:243` is the sole write; `agent.py:88` and `:174`
read it — **after** an `await`. LiveKit gathers one `asyncio.Task` per tool call
(`generation.py:1051-1079`), so when the model emits `lookup_protocol` and `recall_state` in
one turn — both legal, both encouraged by the tool docstrings — task A publishes task B's
`wall_ms` under task A's query string.

> **Shared State:** the failure is silent and self-consistent — a green sub-10ms figure
> attached to the wrong lookup is indistinguishable from a correct one.

**And the badge is green before any data arrives.** `page.tsx:95`:
`stream.latency.worst == null || stream.latency.worst <= 10`. Latency initialises to all
nulls, so the responder screen renders **"within 10ms budget"** during the entire opening
turn. The passing verdict is produced by the *absence* of measurement — displayed most
reliably precisely when nothing has been proven. The literal `10` is also hardcoded
client-side, drifting free of `MOSS_LATENCY_BUDGET_MS` (`config.py:61`).

### P2. The deterministic safety net is attached to the wrong layer — Boundary + Test-Behavior + (prior round: QA, Field, Security)

Established previously and now given its structural name. `hard_escalation_triggered` has
one call site — `agent.py:143`, inside `record_finding` — and its argument is the free text
**the model chose to pass**. The real transcript boundary, `_on_transcript`
(`main.py:128-139`), extracts `text` and does nothing with it but publish to the UI.

> **Boundary:** a rule that exists specifically to backstop model failure cannot be gated on
> the model choosing to call a tool; the guard sits one layer past the edge it was written
> to protect.

Boundary's fix is ten lines: extract a pure `normalize_transcript(event) -> Utterance | None`
and call the classifier there, keeping the model path as a second independent trigger.

### P3. The ratchet is a convention, not a construction — Type Discipline + Domain Model + Shared State

Three personas reached the same conclusion about the project's central safety property from
three different angles.

- **Type Discipline:** `triage.py:82` is an unfrozen `@dataclass` and `:86` declares
  `level: int = 1` — a public mutable `int`, *not* the `Criticality` IntEnum that exists 60
  lines above it. `state.level = 1` bypasses the ratchet and type-checks clean. And
  `max(1, min(5, int(level)))` at `:107` means a model returning `7` silently becomes Level
  5, `0` becomes Level 1 — no error, no span attribute.
- **Shared State:** `agent.py:144` reads `self.state.level`, `:149` writes it, with two
  `await`s inside the critical region. Two concurrent `record_finding` calls both observe
  `level < CRITICAL` before either writes. `mark_escalated` happens to save the double-
  escalation — *"an accident of a boolean flag, not a designed guard"* — and does not save
  `set_level`, whose `history` can interleave.
- **Domain Model:** the invariant is enforced by a comparison the language gives no
  protection to.

### P4. Illegal states are representable, and one is actively reachable — Domain Model + Type Discipline

`escalate_to_clinician` (`agent.py:228-249`) calls `_do_escalate(reason)` and **never
touches `level`**. Verified. So the prompt's own documented case — *"a decision beyond field
first aid"* (`prompts.py:158`) — produces `escalated=True` at Level 1: a **green "Minor"
badge with a red "Clinician bridged" banner directly beneath it**, on both dashboards.

Domain Model's larger point: the escalation lifecycle has five real states —
`NOT_NEEDED`, `REQUESTED`, `CLINICIAN_JOINED`, `CLINICIAN_LOST`, `FAILED_NO_RESPONSE` — and
is modelled as one terminal boolean implementing exactly one transition.

> Three of the missing states are *the failure states*, so the system is structurally
> incapable of telling a responder that help did not arrive.

This is the structural root of the established "escalation notifies no human" blocker: even
with a dispatch transport wired in tomorrow, **there is no state for it to report success or
failure into.** `ABSENT:` no participant-lifecycle listener anywhere — no
`participant_connected` / `participant_disconnected` in `agent/`, no `ParticipantConnected`
in `web/`.

## New findings

### N1. Cross-run doc-ID collision silently merges two patients' records — Idempotency · **verified** · severe

`moss_context.py:105` initialises `_seq = 0` per process; `:113` derives the session index
name purely from the room name; `:303` writes with `MutationOptions(upsert=True)`.

The vendored SDK comment is explicit (`moss_client.py:676-679`): *"Load from cloud if the
index exists — downloads the binary artifact directly and deserializes in-place"*, returning
`loaded_doc_count`.

So a second agent run against a previously-archived room **resumes the old documents**, then
overwrites `fact-00001` onward with the new incident's facts. Replaying does not converge —
it silently interleaves two patients into one clinical record.

The SDK hands back `loaded_doc_count`, the signal that would detect the resume, and
`connect()` discards it. Fix is one line: make the index name unique per run.

### N2. Durability runs behind an unbounded LLM call — Idempotency · **verified**

`main.py:141-162`, docstring included: *"Close out the incident: SOAP note, then archive the
Moss index."* `generate_soap_note` — an OpenAI call with no timeout (established) — sits
**ahead of** the only durability step. The `try/except` catches a SOAP exception but not a
hang or a SIGKILL. Everything before `main.py:158` is lost.

The audit trail is the thing that must survive; the SOAP note is the thing that can be
regenerated from it. The ordering is backwards.

### N3. Reconnect resets the ratchet to Level 1 — Idempotency

`page.tsx:39-42` flips to `"idle"` on disconnect; `useTriageStream` accumulates from `EMPTY`
with no replay. A mid-incident WebRTC drop returns the responder to `level = 1`, *"Awaiting
assessment"*, `escalated = False`.

> The ratchet is carefully written to prevent a quiet downgrade within a run, and a reconnect
> defeats it completely — a patient assessed Critical is silently displayed as Minor, which
> is the exact failure the ratchet exists to prevent.

### N4. Escalation has no idempotency key — Idempotency

`triage.py:134`'s docstring claims "Idempotent" and is correct *within one process lifetime*
— the guard is a boolean on an object constructed fresh at `main.py:64`. After any restart
it is `False` and `_do_escalate` fires again.

> **Fixing the dispatch blocker without an idempotency key converts a silent no-op into
> duplicate pages.**

### N5. Five of eight boundaries have no parse step — Boundary

| # | Entry point | Guard |
|---|---|---|
| 1 | `POST /api/token` body | Partial — shape regex only |
| 2 | Env / config | Partial — 2 of 5 secrets via `_req` |
| 3 | LiveKit room name → `session_id` | `ABSENT:` |
| 4 | STT transcript | `ABSENT:` |
| 5 | LLM tool arguments | Scattered inward, not at edge |
| 6 | Moss retrieval results | `ABSENT:` |
| 7 | Browser data-channel receive | `ABSENT:` beyond `JSON.parse` |
| 8 | LLM completion (SOAP) | `ABSENT:` |

The browser path is the sharpest: `useTriageStream.ts:49` is
`JSON.parse(...) as TriageEnvelope` — a bare assertion whose `try/catch` guards JSON syntax
only. A well-formed hostile frame becomes fully-trusted domain state. Downstream,
`LEVEL_STYLES[level] ?? LEVEL_STYLES[1]` (`page.tsx:94`, `doctor/page.tsx:68`) silently
converts a corrupt Level 5 into a **green Level 1**.

### N6. The SOAP note has no structural type — Boundary

`soap.py:98` is `return (response.choices[0].message.content or "").strip()` — the entire
parse of a completion a clinician and an audit body will read. The prompt demands four
sections and a provenance line; nothing verifies any arrived. A refusal, a truncation, and a
correct note are indistinguishable `str`s published as the incident record.

### N7. Windows runs concurrent incidents in one process with shared telemetry globals — Shared State

`worker.py:126-130` sets `JobExecutorType.THREAD` on `win32` — one thread per job, **same
process**. `telemetry.py:31-32` holds `_INITIALISED` / `_TRACER` as module globals with a
check-then-set at `:67`/`:92` and no lock. Two near-simultaneous rooms can both pass the
guard; OTel keeps the first provider, so the second session's spans export carrying the
*first* session's resource attributes.

DESIGN.md's NFR-006 plans for "5 concurrent incidents" against an isolation model the
Windows default does not provide.

### N8. The one lock guards the cheap half — Shared State · **verified**

`moss_context.py:269-271` holds `self._lock` for `self._seq += 1` and releases it **before**
`await session.add_docs(...)` at `:301`. The lock makes `_seq` unique; it does not make the
index ordered, which is the only reason a sequence number exists. Both writes then hop to
the same bounded executor where the OS scheduler decides order.

### N9. No type checker runs on either surface — Type Discipline · **verified**

`ABSENT:` no mypy, pyright, or config anywhere in `agent/`. Every annotation is documentation
nothing verifies — including `noqa: ANN401` comments suppressing a linter that is also not
installed. TS has `strict: true` (`tsconfig.json:6`) but **no `typecheck` script**; the only
enforcement is whatever `next build` happens to do, and nothing in the repo runs it.

### N10. `FACT_KINDS` silently swallows unknown kinds, and the model is shown a different list — Domain Model + Type Discipline

`moss_context.py:48` declares five kinds; `:266-267` coerces anything unrecognised to
`"observation"` with **no log and no span attribute**. The tool docstring the model reads
(`agent.py:134`) advertises only four — omitting `escalation`. A model saying
`kind="medication"`, or `"Vital"` (the check is case-sensitive), produces a fact filed as an
observation that the SOAP note and both timelines render as fact.

`"dispatch"` is advertised and accepted but **produced by nothing** — a domain concept
declared as a string with no code behind it, exactly like `distress_score`.

### N11. The criticality ladder is modelled three times — Domain Model

`triage.py:20-48` (IntEnum, good), `types.ts:81-87` (`Record<number, ...>` keyed by number
rather than the `1|2|3|4|5` union declared eight lines above), and again as prose in
`agent.py:205-206` and `prompts.py:249`. A sixth level added in Python type-checks fine in
TS and renders green Level 1.

## What these lenses judged well

- **`triage.py` is the best-factored file in the repo, and four personas said so
  independently.** Stdlib-only imports, no I/O, no framework — Test-Behavior drove the
  ratchet, `mark_escalated`, `should_escalate` and `hard_escalation_triggered` in one process
  with zero setup. Boundary: *"the failure is that nothing calls it from the right edge, not
  that the logic leaked."*
- **The agent's tool layer is testable with hand-written fakes** — Test-Behavior verified
  this against expectation, driving `record_finding` through the full escalation path with a
  `MagicMock` and a plain `async def publish`, getting the literal topic sequence out. So the
  testable surface is *larger* than DESIGN.md assumes.
- **The injected `Publisher` seam** (`agent.py:53`, wired at `main.py:66-86`) is what makes
  that possible — a deliberate choice that paid off.
- **`_annotate` records both clocks** — wall-clock alongside Moss's self-reported
  `time_taken_ms` (`moss_context.py:227-236`). Recording both the caller's clock and the
  callee's claim is exactly what defeats the usual latency proxy. The measurement *design* is
  sound; only its execution and its storage slot are not.
- **`TriageEnvelope` is a proper discriminated union** with an exhaustive reducer
  (`types.ts:73-79`, `useTriageStream.ts:54-94`) — the right shape, undermined only by
  untrusted inputs.
- **Config is parsed once at the edge into frozen dataclasses** — Boundary called it *"the
  one place the codebase already does what the rest of it should."*
- **OBS-001 is the model acceptance criterion to copy** — *"distinct trace IDs per session
  must equal 1"* names the value to read and the literal to compare. Test-Behavior
  recommends rewriting five other criteria in that shape.

## The single thing most likely to sink this

Unchanged from the prior review: **the escalation beat**. Nothing in this round contradicts
it, and Domain Model deepened it — the lifecycle has five real states modelled as one
terminal boolean, three of the missing ones being the failure states, so there is nowhere for
a dispatch transport to report into even once one is built.

**But this round adds a second thing that could sink the demo specifically**, and it is
cheaper to fix:

**The latency claim — the one thing the Moss sprint judges on — is unproven, misattributable,
and displayed green before measurement.** It has never been executed (no `.env.local`, no
`__pycache__` in `agent/scripts/`). Its number can be published under the wrong query
whenever the model emits two tool calls in one turn. And the on-screen badge reports
"within 10ms budget" while `worst` is still `null`.

Actions 2, 4 and 5 close all three in well under a day, and they protect the claim the
project is actually being judged on.
